## Собственный проект

Тема проекта: каталог игр

Главный класс: Game

Почему этот объект нужен программе:
Game описывает одну игру в каталоге: её название, жанр, год выхода и рейтинг.
Без такого класса пришлось бы заводить по 4 отдельные переменные на каждую игру,
а с классом все данные одной игры хранятся вместе, и игр можно создавать сколько угодно.

Какие данные хранит объект:

- Title (название игры, string)
- Genre (жанр, string)
- ReleaseYear (год выхода, int)
- Rating (рейтинг от 0 до 10, double)

Какие значения задаются через конструктор:
Title, Genre, ReleaseYear — эти данные у каждой игры свои и известны при создании.

Какие значения можно задавать автоматически:
Rating — у новой игры в каталоге рейтинга ещё нет, поэтому конструктор ставит Rating = 0.
Какое значение я решил задавать автоматически и почему?
Rating = 0. У только что добавленной в каталог игры ещё нет оценок,
поэтому логично, что её рейтинг начинается с нуля. Передавать 0 при каждом
создании объекта было бы лишним — конструктор ставит его сам.

## Шаг Г
**Класс и его назначение:** 
Game (видеоигра). Хранит название, жанр, год выпуска, рейтинг и время игры.

**Какие данные защищены и почему:**
- `Title` — защищен от пустых строк и лишних пробелов.
- `PlayTime` — защищен от отрицательных значений (нельзя отмотать время назад).
- `Rating` — защищен от выхода за пределы от 0 до 10.

**Какие свойства имеют private set:**
`PlayTime`, `Rating`.

**Какое свойство использует закрытое поле:**
`Title` (использует поле `_title` для хранения очищенной строки).

**Что проверяют конструктор и методы:**
- Конструктор задает начальные значения (`Rating = 0`, `PlayTime = 0`) и запускает проверку имени.
- `AddPlayTime()` игнорирует отрицательные значения (защита времени).
- `ChangeRating()` ограничивает рейтинг диапазоном от 0 до 10 (защита рейтинга).

**Проверки двух объектов и полученные результаты:**
- `game1` ("GTA V"): при попытке поставить рейтинг 15, он стал 10. Название очистилось от пробелов.
- `game2` ("Minecraft"): при попытке поставить рейтинг -5, он стал 0.
- Изменение `game1` никак не повлияло на `game2` (объекты независимы).

## Шаг Д
### Защита состояния Hero

- **Почему методы ПР №2 не защищали:** Поля были `public`, любой мог напрямую написать `alexander.Health = -100;` в обход методов.
- **Отличие get, set, private set:** `get` — чтение, `set` — запись для всех, `private set` — запись только внутри класса.
- **Где проверяется начальное здоровье:** В конструкторе (`if (MaxHealth <= 0)`, `if (Health < 0)` и т.д.).
- **Как Heal сохраняет MaxHealth:** Считает `missingHealth`. Если лечение больше, ставит `Health = MaxHealth`, иначе прибавляет.
- **Как Name использует _name и value:** `value` (из `set`) очищается через `Trim()` и сохраняется в поле `_name`.
- **Почему в конструкторе `Name = name;`:** Чтобы запустить проверку из свойства. Запись `_name = name;` обошла бы её.

### Проверки
- **Конструктор:** `-100` → `0/100`; `5000` → `200/200`.
- **Урон/лечение:** Александр (`150/150`): урон 30 → 120, лечение 10 → 130, лечение 5000 → 150. Лечение `-20` проигнорировано.
- **Имя:** `"   Александр   "` → `"Александр"`. `"   "` → `"Безымянный герой"`.
- **Внешняя запись:** `alexander.Health = -100;` не скомпилировалась (ошибка CS0272 из-за `private set`).

### Доп. часть В. Банк ошибок
1. Ошибка: `if (amount >= 0)`. Исправление: `if (amount <= 0)`. Проверка: лечение сработало (здоровье 80).
2. Ошибка: `Health -= amount`. Исправление: `Health += amount`. Проверка: здоровье увеличилось.
3. Ошибка: `Health = amount`. Исправление: `Health = MaxHealth`. Проверка: при лечении 5000 здоровье стало 150, а не 5000.
